# FHK Gear repair ledger

2026-10-04. Candidate 0.3.0. Original baseline: [62-finding audit](AUDIT_2026-10-04.md). Player authorized implementation; the original audit remains unchanged.

**FHK Gear is not complete. This candidate uses approximate scores, not simulated DPS.** Fixed below means an E1/E2 implementation addresses the reported failure. It does not close an in-game acceptance gate. Mitigated means the unsafe case stays manual or coverage remains incomplete. Open means the model/feature is not implemented.

## Audit findings

### G01: Bind confirmation can accept another item

**Status:** fixed. **Original severity:** Critical. **Evidence:** E1/E2 only.

Owned transaction, full cursor link and exact target are required. Both confirmation settings default off. Same-ID-only cursor data now fails closed.

### G02: Incomplete tooltip data is cached as usable

**Status:** fixed. **Original severity:** Critical. **Evidence:** E1/E2 only.

Empty/incomplete tooltip/stat data stays pending and uncached. Unknown RGB is not a usable requirement.

### G03: Quest choice ignores better gear already in bags

**Status:** fixed. **Original severity:** Critical. **Evidence:** E1/E2 only.

Quest/roll baseline searches legal worn/bag setups, rather than greedy additions. Unknown facts or 10,000-node exhaustion leave choice manual. Weapon reward pairing remains under G05.

### G04: Quest callbacks survive the quest window

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Quest generation and open-window state gate item continuations; QUEST_FINISHED cancels them.

### G05: A better MH/OH pair cannot replace a two-hander

**Status:** mitigated. **Original severity:** High. **Evidence:** E1/E2 only.

Complete MH/OH recommendations and legal baseline exist. Automatic multi-step swaps are disabled. Reward-plus-partner and off-hand hover while wearing 2H remain unfinished.

### G06: Weapon-style constraints are only partly enforced

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Weapon-style filters apply to all melee equip locations; dagger main-hand and dual-wield checks have fixtures.

### G07: A second ordinary copy is mistaken for the worn item

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Identical ordinary copies can upgrade the other ring/trinket slot. Physical bag/source keys prevent using one copy twice.

### G08: Unique-equipped categories are not enforced

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Unique-equipped categories and smallest applicable category limit apply across complete setups.

### G09: Inactive set procs are scored as active

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Set effects are stored separately and activated once at their threshold. Unknown thresholds/effects stay manual.

### G10: Rating fields are treated as percentage points

**Status:** mitigated. **Original severity:** Medium. **Evidence:** E1/E2 only.

Explicit percentage lines win. Raw ratings require selected units/conversions; otherwise they cannot drive automation. Actual Forever conversion still needs E3.

### G11: Equivalent stat sources can double count

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Equivalent rating/stat aliases and Equip sources are reconciled. Separate school spell damage remains distinct.

### G12: Failed equips are not confirmed and can hide fallbacks

**Status:** fixed. **Original severity:** High. **Evidence:** E1/E2 only.

Equipped-link acknowledgement, bounded failed-source exclusion, eligible fallback and a general free-space check for displaced off hand. Multi-step rollback is not enabled.

### G13: A locked best bag item blocks unrelated upgrades

**Status:** fixed. **Original severity:** Medium. **Evidence:** E1/E2 only.

Locked/failed sources are filtered before best-per-slot selection.

### G14: Loot rolling does not honour Greed availability

**Status:** fixed. **Original severity:** Medium. **Evidence:** E1/E2 only.

Need/Greed availability is respected; independent policies and owned confirmation toggle added; roll cancellation clears work.

### G15: Named weight import drops digit keys and misreads exponents

**Status:** fixed. **Original severity:** Medium. **Evidence:** E1/E2 only.

Whole numeric tokens, native digit keys and exponents parse; malformed, duplicate, infinite and conflicting values are rejected.

### G16: Pawn export loses effective weights and units

**Status:** mitigated. **Original severity:** Medium. **Evidence:** E1/E2 only.

Native FHKW:2 preserves effective supported weights. Pawn cannot preserve all units/damage-only semantics; its row explains the limitation and requires Pawn installed.

### G17: AutoGear migration replaces adjusted defaults and aliases its tables

**Status:** fixed. **Original severity:** Medium. **Evidence:** E1/E2 only.

Migration deep-copies valid values and merges sparse imported weights over adjusted defaults. Reviewed locks are stored separately.

### G18: School shares are not an ability model

**Status:** mitigated. **Original severity:** Medium. **Evidence:** E1/E2 only.

Cached highest-learned-rank context and three sourced reference abilities exist. This is not complete school-share, talent or rotation coverage.

### G19: Proc frequency and uptime use universal assumptions

**Status:** mitigated. **Original severity:** Medium. **Evidence:** E1/E2 only.

Typed rates, explicit melee participation, chance/PPM/ICD overrides and fight-length Use availability replace universal assumptions. Server rates, special-attack eligibility and shared cooldown groups still need evidence.

### G20: Proc valuation confuses item slot with damage participation

**Status:** fixed. **Original severity:** Medium. **Evidence:** E1/E2 only.

Direct proc damage uses a common damage objective. Participation is an explicit setting rather than the ratio of DPS weights. This is still an approximate score.

### G21: Effect parser accepts partial effects and false buff matches

## Additional player requirements

- Automation defaults OFF. Separate Need on Upgrades, Greed on Other Loot, Confirm Gear Equip Binds and Confirm Gear Loot Rolls controls are implemented. Confirmation toggles default OFF. Coloured rarity cap defaults Green; eligible greys remain upgrades; higher rarities keep marks.
- Marker styles, separate Greed style, size, opacity, position/offsets and colours use Ellesmere widgets. Extra bag/roll/character markers default OFF. Runtime rendering is unverified.
- Permanent explicit stat enchants are reconciled with structured totals. Unknown proc/weapon-damage enchants and temporary/imbue effects leave setups manual. Future-enchant costs, effects and talent interactions are not simulated.
- The learned context currently has only Aimed Shot, Backstab and Frostbolt reference records. Hunter talent ranks are read but modifiers are not applied. Ability Adjusted is experimental and cannot authorize automatic choices.
- MythicSim export appears only with its exporter installed. Its default raid simulation is not a levelling model. Pawn is compatibility only. ForeverGear uses only its public API.

## Performance evidence and limits

Mocks assert one provider readiness read per complete bag pass; 100 warm hovers add no item-stat reads; 20 skill events coalesce into one context timer. Cursor retries stop, pending maps have limits and exact setup search is capped at 10,000 nodes. No permanent OnUpdate was added. Active full-bag reads and search allocations still exist. These are call/count checks, not CPU/FPS measurements. Compare real CPU against plan 4.6 before claiming performance closure.

## In-game acceptance checklist

1. Fully exit and restart WoW. Run `/fhkgear status`, `/fhkgear context` and `/fhkgear errors`. Expect 0.3.0; missing APIs must be reported without errors or accidental actions.
2. Open Gear and visit all five pages. Use Ellesmere search, switch away/back and change spec/source/phase. Expect current control state, correct placement and no extra actions from hidden search builds.
3. Leave AutoGear enabled and enable Gear auto-equip. Expect marks only. Use Disable AutoGear and verify only this character is changed after the prompted reload.
4. At level 1, compare a usable better grey with the starter grey. Cap Grey, then Green; expect eligible improvements to equip only when auto-equip is enabled. Hover an epic with cap Green; expect a mark and no equip.
5. Hover an item with explicit crit/hit percentage and run `/fhkgear item`. Record structured values and the Equip line. On a rating-only item, expect manual until its actual units/conversion are supplied.
6. Hover an item with Chance on hit and a Use item; run `/fhkgear item`. Expect typed Proc lines and rate/source assumptions. Enter a known PPM or chance+ICD; verify only that item changes. Measure enough eligible hits/time to establish the server rate separately.
7. Compare a weapon with an explicit +Agility enchant against its plain version; expect one stat addition. Hover an unknown proc enchant and apply a temporary weapon buff; expect uncertainty/manual automatic choice, not an invented DPS gain.
8. Lock main/off-hand separately. Compare MH+OH against a two-hander and a better bag pair. Expect whole-setup recommendation, preserved locks and no automatic multi-step pair execution. Fill general bags and try a two-hander that removes an off hand; expect no automatic attempt.
9. Try a locked best bag item, then an unlocked lesser upgrade; expect the unlocked candidate to remain eligible. Pick up another item before the scheduled equip; expect the cursor to remain yours.
10. With Confirm Gear Equip Binds OFF, trigger a Gear-owned eligible BoE equip; expect a manual prompt. Repeat ON; expect only its matching target/link to confirm. Manually trigger an unrelated bind; expect no Gear confirmation.
11. Open a quest with a non-gear choice; expect manual. Test a reward already exceeded by owned bag gear; expect no redundant upgrade. Test vendor stacks; expect quantity-adjusted value. Close a pending quest before item data loads; expect no later reward claim.
12. Enable Auto-Roll and Need on Upgrades. Test an upgrade with Need permitted; expect Need. Test an item with Greed prohibited; expect no Greed. Turn Need on Upgrades OFF; upgrade stays marked and roll stays manual. Toggle Confirm Gear Loot Rolls and verify only Gear's matching roll can be confirmed.
13. Enable bag, roll and character markers. Change each style/colour, opacity, size and offsets; inspect native and Ellesmere bags. Hover a bag item to exercise public-owner discovery. Turn marks off; expect all existing overlays to hide. Cancel a roll/quest; expect its marks to clear.
14. Add/remove an item-ID exclusion, a full enchanted-link variant exclusion and slot lock. Expect only the selected scope to be excluded. Review AutoGear lock import before confirming it.
15. Select Approximate Stat Weights, then Ability Adjusted. Verify learned ranks and cast controls. Expect experimental/unknown modelling to stay manual; no simulated-DPS claim.
16. Equip two items sharing a Unique-Equipped category; expect illegal combined candidates blocked. Compare inactive/active set thresholds; expect each active bonus counted once.
17. Try matching and mismatching bow/gun quivers/ammo pouches. Compare an empty bag-slot upgrade with auto bag replacement OFF/ON. Occupied bag replacement must remain manual.
18. Test level 59, then reach 60 with Levelling Mode ON; expect automation to stop at 60 while marks remain. Turn Levelling Mode OFF deliberately; inspect the control state before further actions.
19. With the companion installed, export/import/switch an Ellesmere profile. Expect Gear look/modes to transfer; locks/weight libraries only transfer when their own opt-ins are ON. Per-character ownership snapshots must stay local.
20. With Pawn/MythicSim/ForeverGear absent, expect their unavailable export/source controls hidden or saved provider marked Unavailable (Manual). Install a permitted exporter separately and verify it opens its own export UI.
21. Hover/scour bags after training a weapon proficiency, learning a rank and changing talents. Expect refreshed requirements/context. Measure real addon CPU while idle, hovering and handling bag events; record bag size and mode.
